# 個人檔案與 Agent 串接界線

目前已實作 /profile 頁面與 GET／PUT /api/profile。登入後进入頁面會依 session 載入本人資料；登入成功仍導向 /home，不從帳密推測姓名、生日。未建立時 GET 回傳 profile: null。

PUT 是本人手動保存完整表單：name、birthDate、area、phone 四項必填；其他欄位禁止。要求可信 Origin 與使用者 cookie；以 session 決定 owner，不接受 userId。不更新申請草稿或被照顧者資料，不構成代填或送件授權。多分頁同時編輯目前採最後成功儲存覆蓋，尚未提供版本衝突檢查。

## Agent 組員後續串接

- 本次沒有修改 Agent，也沒有提供自動填入／覆寫工具。
- profiles 現有四欄皆 NOT NULL；尚未建立 profile 且對話僅取得電話時，不能直接用此 API 寫入部分檔案，不得使用假生日或空字串補齊。須另行設計可空欄位 migration 或待確認建議資料。
- 只有明確屬於登入使用者的資訊可提出填入建議；申請人未必是登入者，被照顧者更不能直接視為登入者。
- 未填欄位可在安全規則就緒後補入並告知使用者；已存在且不同的內容，先呈現差異、取得同意，不可直接使用此完整覆寫 API。
- 後續自動補入需在 API method 原子性檢查空欄位／資料版本，避免競態覆蓋使用者手動修改。
- 所有 owner 取自可信登入身分；模型不提供可自由指定的 userId。
- 不把完整 profile、電話或其他個資放入 URL、log 或模型上下文。比賽僅用虛構資料。

## 測試

登入後從右上角「已登入」左側的人像圖示進入個人檔案，填四項虛構資料儲存，重新整理確認重讀；切換帳號確認資料隔離。API 自動測試使用 mock，不寫真實資料庫。此變更沿用 profiles 表，不需 migration。
